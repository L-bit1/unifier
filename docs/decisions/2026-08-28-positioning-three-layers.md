# 2026-08-28 · 联合器定位：开屏 / 本质 / 护城河

## 结论

**「手机上操控电脑的 AI」是表象与入门钩子，不是最终目标。**  
若终点定成远程操控，格局会收成向日葵/TeamViewer 的替代品。

## 三层

| 层 | 用户感知 | 产品实质 |
|----|----------|----------|
| 表象（开屏） | 地铁飞书派活，回家电脑已改 | 手机/飞书/App = 输入通道；遥控的是 Cursor/Trae，不是鼠标键盘 |
| 本质（内核） | 多机多 Agent 协作 | Hub 调度写码 / 审查 / 测试角色；状态机 + 审查闸门 + slots |
| 护城河（终极） | 「AI 改过什么、为何改」可查 | 意图 + 决策链 + 上下文的飞行记录仪（黑匣子）；不替代 GitHub 存代码 |

## 对外话术

1. **第一句**（好懂）：用手机指挥 AI 写代码。  
2. **第二句**（建壁垒）：更像 AI 编程的调度台 + 黑匣子——每个 AI 改动有据可查、每个角色听指挥。

## 一句话终极目标

> AI 编程时代的人机协作操作系统：手机只是输入设备之一，飞书只是通道之一；产出是可管理、可审计、可规模化的 AI 开发团队。

## 对工程的含义

- 开屏体验（App / 飞书闭环）要做，但是**获客钩子**。  
- 优先级上：**调度正确性 + Manifest/审计检索** ≥ 单纯「更像远程桌面」。  
- Cursor 回传进 App：属于通道体验，应接到 Hub agent-reply，而不是另造远程桌面协议。
